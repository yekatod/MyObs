**1. Что такое value type и reference type?** **Назови примеры каждого.** [Must know]

>**Объект типа значений хранит своё значение, а объект ссылочного типа хранит ссылку на своё значение. Типы значений представлены встроенными типами, к примеру decimal****, int****, enum****, struct** **и тд. Типы ссылок представлены Class****, delegate****, string** **и тд. Различия между типами значений и типами ссылок заключаются в:**

>**- Расположение: в основном, типы значений лежат в стеке (исключая поля классов), а типы ссылок – heap** **(сам объект, ссылка остаётся в stack****)**

>**-При сравнении типов значений происходит сравнение по их значению, а у типов ссылок без переопределения по умолчанию происходит сравнение по ссылке.**

>**- При присваивании данных тип значений будет копировать значения, а тип ссылок – копировать ссылку на значение**

**2. Что происходит при присваивании одной переменной класса другой? А одной struct****-переменной другой?** [Must know]

>**При присваивании в разрезе класса будет скопирована ссылка, т.е. обе переменные будут иметь доступ к одному и тому же экземпляру. Для структуры характерно поведение копирования значения**

**3. Почему утверждение «value** **types** **всегда лежат в Stack****, reference** **types** **всегда в Heap****» неверно?** [Must know]

**Тип значения может лежать в хипе, если он является частью объекта типа значений (например поле класса), а ссылка на экземпляр типа ссылки всегда будет лежать в стэке**

**4. Что такое Stack, Heap и stack frame?** [Must know]

Это всё адресные пространства для хранения памяти

**Стек – адресное пространство для хранения в основном типов значений. Является базой, где во время выполнения выделяются фреймы (условно показывающие нам область видимости, то есть фрейм новый будет выделяться при вызове метода и в этот фрейм будут добавляться все инициализированные в нём же данные с учётом параметров). При выходе из метода стек очищается – фрейм и его внутренности удаляются. Работает принцип LIFO****. Хип же предназначен для хранения типов ссылок, это неупорядоченное, в отличие от стека, хранилище, где у каждой «ячейки» есть свой адрес – ссылка. При инициализации объекта типа ссылки в стек добавляется ссылка на объект и в хипе по этой ссылке непосредственно создаётся сам экземпляр с его внутренними значениями. Хип очищается при помощи механики GC****. Хип медленнее стека за счёт того, что его пространство не упорядочено**

**5. Что примерно происходит при `var** **user** **= new** **User****();`?** [Must know]

**При инициализации переменной происходит следующее: в стеке создаётся ссылка на ячейку хипа, куда ляжет экземпляр. Экземпляр ложится на выделенную ячейку хипа**

**6. Зачем нужен Garbage** **Collector****? Как он понимает, что объект можно собрать?** [Must know]

**GC** **является встроенным механизмом очистки памяти. оканчивается память механизмы GC** **проходятся по рутам приложения (стек) и выделяют достижимые объекты. Далее для каждого достижимого объекта по очереди собирается условное дерево достижимости. Так GC** **помечает все объекты, которые еще видимы и активны в рамках приложения. Оставшиеся объекты выделяются как недостижимые, они и будут очищены**

**7. Что такое поколения GC****: Gen****0, Gen****1, Gen****2? Зачем они нужны?** [Must know]

**Поколения нужны для оптимизации процессов очистки памяти. Когда оканчивается память под новые объекты, первоначально GC** **проводит уплотнение по поколению 0 (где 0 – самые свежие объекты, т.е. те, которые потенциально будут жить меньше, а 1 и 2 более устойчивые. ГК проходится по 0 поколению и уплотняет его. В первый круг. Все выжившие объекты переводятся в первое поколение. Далее в том же порядке с 0 по 2 поколение происходит уплотнение, объекты из 0 и 1 поколения будут сдвигаться в поколения выше. Таким образом если достаточно памяти при уплотнении 0 поколения GC** **остановится на этом моменте и не будет тратить ресурсы на очистку поколений выше**

**8. Что такое LOH** **и почему большие объекты рассматриваются отдельно?** [Must know]

**LOH – large objects heap,** **куча** **для** **больших** **объектов.** **Они выделены в отдельную кучу, чтобы ГК не тратил ресурсы на уплотнение памяти и перемещение больших объектов, а просто очищал неактуальные данные**
